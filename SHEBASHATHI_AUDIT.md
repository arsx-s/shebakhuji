# ShebaShathi audit and remediation

Original audit: 2026-10-16. Updated after the frontend rebuild and backend fixes:
2026-10-18.

## What the audit found (pre-rebuild)

- A monolithic `app.js` plus a half-finished `frontend-api.js` and a text-swap
  `i18n.js` — three overlapping sources of truth for rendering, data and
  language.
- Client-only role checks; the API existed but the UI did not consistently use it.
- Dead controls: listeners bound to elements that re-rendering destroyed, modals
  that opened over stale DOM, buttons with no handler.
- Language switching that replaced leaf text nodes, leaving half-translated pages
  and raw keys after re-render.
- Settings/reviews/maps presented as working when they were local-only or
  placeholders.
- No automated tests, no static checks.

## What was fixed

### Frontend (rebuilt)

- One modular ES-module app (`src/`) with a single render loop, so URL, session
  and screen can no longer disagree.
- A proven **action bus**: a button without a registered handler logs a warning
  instead of silently doing nothing.
- Central bilingual dictionaries (`src/i18n.js`) with a test that fails the build
  if the two languages drift, plus enum coverage for every status the server can
  return. No raw keys; dynamic server values go through static lookup maps.
- Deep links survive a cold load (the boot no longer bounces a guarded deep link
  to the landing page before the session is restored).
- Real Bengali typography: a system font stack with Bengali fallbacks, verified
  Bangla wrapping at 320/390/768/desktop widths.
- Original illustrations and brand assets generated by a committed script; service
  photography stored locally. No CDN, no external font, no remote image that can
  disappear.
- Responsive fixes found by measurement: the public header no longer overflows at
  ≤390px, the app-bar labels collapse on narrow phones, and page headers with a
  side panel stack instead of squeezing the title.
- Recovered a **computed-but-never-rendered** block: the booking wizard built the
  add-on picker and then dropped it from the template, so add-ons could be priced
  by the server but never chosen by a customer. The block is rendered again (the
  review line already existed), verified end-to-end, and a new static check
  (`scripts/check-blocks.js`) fails the build whenever a markup block is built and
  never interpolated.

### Backend

- Role checks now return **403 when authenticated but wrong role** (was 401,
  which logged users out).
- `GET /api/me` returns `200 {user:null}` for anonymous instead of an error.
- Path segments are URI-decoded.
- Static files send ETag/Last-Modified/`no-store`/`nosniff` and honour 304.
- Commission/fee settings are published to clients via `/api/public/stats`.
- Fixed a 500 on booking with add-ons (`listing.addOns` could be undefined).
- Booking detail returns the review; marketplace listings filter by service.
- `normalizeDb()` backfills new fields so older data keeps working.

### Accessibility and offline (added 2026-10-18)

A Lighthouse pass over every screen surfaced real defects, all now fixed:

- **Colour contrast.** The brand copper `#C8703F` failed AA for white text on
  filled buttons (3.6:1) and for eyebrow text on light backgrounds (3.3:1); the
  muted grey failed on the canvas (4.4:1). Added `--copper-ink #8A4423` for copper
  *text* and use `--copper-dark #A5542A` for filled surfaces (5.4:1); `--muted` is
  now `#616A78` (5.0:1 on canvas, 4.6:1 on chips). `--warn` was also darkened to
  clear AA on its soft background.
- **Heading order.** Empty/error states, the footer, public section cards and the
  booking-detail cards used `<h3>` where no `<h2>` preceded them. They are now
  `<h2 class="h3">` so the visual size is unchanged and the outline is valid.
- **Accessible names.** The brand link and the language button carried
  `aria-label`s that disagreed with their visible text (WCAG 2.5.3 / axe
  `label-content-name-mismatch`); the notification bell omitted its unread badge
  from its name. All three now include the visible text.
- **Invalid ARIA.** The activity/inbox segmented controls used `aria-pressed` on
  `role="tab"` (use `aria-selected`), and a static skill chip carried
  `aria-pressed` on a non-interactive `<span>`.
- **Transient toast contrast.** Toasts faded in, so a mid-animation sample
  measured 3.4:1. The entrance/exit animation now uses transform only and the text
  stays fully opaque for the toast's whole life.
- **Service worker never registered.** `registerServiceWorker()` ran after the
  boot `await`s, so `window.addEventListener('load', …)` never fired and the PWA
  shell was dead code. It now registers immediately when the document is already
  complete. Verified by unregistering, reloading, and confirming the app
  self-registers, activates and caches 25 shell assets — and by loading a page
  with the network emulated offline (API `Failed to fetch`, HTML/CSS served from
  cache, no broken images).

### Verified

- `npm run check`: 15 modules parse, all referenced assets/icons exist, number
  inputs accept ordinary values.
- `npm test`: 25/25, including an isolated API suite on a throwaway database.
- Lighthouse, 27 routes: **Accessibility 100, Best Practices 100, SEO 100** on the
  landing, how-it-works, providers, support, register, not-found, customer
  home/explore/service/provider-profile/booking-wizard/booking-detail/activity/
  inbox/conversation/offers/account/addresses/support pages, provider
  work/requests/schedule/earnings/listings, and the admin console and all six of
  its sections.
- Browser end-to-end: registration/login, booking lifecycle through completion and
  review, open-bidding offer → accept → booking, chat, admin console, language
  switch persistence, deep links, and responsive layout at four widths.
- Development data restored to its pre-QA state (backup in `data/backups/`).

## Remaining — genuine, not hidden

- **Android APK not produced.** No JDK/Android SDK in this environment; only the
  web bundle and Capacitor sync can be prepared. See `ANDROID_BUILD.md`.
- **No payment gateway.** Totals, invoices and ledger entries are recorded, but
  no money moves; the UI says "pay in cash / unpaid" rather than faking a charge.
- **No SMS/email OTP.** `AUTH_MODE=development` password login only.
- **No live map/GPS/ETA.** The booking map is a labelled approximation of the
  saved address.
- **Single-process JSON store.** No transactions or cross-process locking; two
  server processes will clobber each other. Migration path in
  `DATABASE_ARCHITECTURE.md`.
- **No CI.** Checks and tests are commands a human runs.
- Ratings/verification badges reflect stored demo data, not an external identity
  provider.

## How to reproduce the verification

```powershell
npm run check
npm test
npm start        # then open http://localhost:3000
```

Then walk: register → explore → book → provider advances the job → customer
confirms → review; and: publish an offer-mode request → provider quotes →
customer accepts. Both languages, at desktop and phone widths.

For the accessibility pass, open a route and run Lighthouse against the tab; the
target is Accessibility 100 / Best Practices 100 / SEO 100 with no listed
failures. For the offline shell, load the app once (so the service worker
installs), then reload with the network emulated offline — the shell must still
render from cache while API calls fail.
